# 功能扩展方向

更新日期：2026-10-26。依据本地代码、Git 历史和现有交付清单整理。以下为候选方向，不代表已经决定实施。

## 已有能力，不重复列为开发目标

本地两／三人、PvP／合作、五类道具、三档 AI 难度、战绩、音效、拖尾／危险提示、结算慢镜、菜单及转场均已有实现。

历史节点：`1ff926a` 加入第三名玩家；`7de40ed` 扩展合作、难度、地图框架、音效、战绩和演示；`23e9df9` 调整合作节奏；后续多次调整无敌与冲击波。`5573953` 完成双层菜单和 Unity 6.3 构建，已通过 PR #1 合入远端 main。

暂停、重开、返回、基础平衡调整属于现有功能维护，不作为新增玩法目标。当前同时出界采用首次结算锁定结果，是否改判属于规则选择，本轮保留现状。

## 候选功能

| 优先级 | 方向 | 玩家能体验到的变化 | 可复用基础 | 相对投入 |
|---|---|---|---|---|
| 1 | 机关地图内容包 | 中央挡板、往返移动障碍、不同宽高场地，让推挤路线产生变化 | `ArenaPreset`、`ArenaLoader`、`ObstacleMover` 已有；需要制作实际地图和明确进入方式 | 中 |
| 2 | AI 行为种类 | 普通追击之外增加蓄力冲撞、短时重装、保持距离的骚扰球，让合作模式需要辨认和应对不同敌人 | `AIController`、`AISpawner`、现有危险提示；需增加行为配置、前摇与可辨识外观 | 中 |
| 3 | 合作波次与挑战目标 | 从无限生存扩展为“撑过指定波次”“保护目标”“精英波次”，形成阶段奖励和明确通关目标 | 现有合作计时、生成器与结算；需新增波次规则、目标和通关结果 | 中至高 |
| 4 | 自定义对局规则 | 选择道具池、是否刷 AI、轮盘与收缩节奏，组合纯推挤或混乱派对玩法 | `GameSession`、各生成器和轮盘；需独立规则配置并记录本局规则 | 中 |
| 5 | 多局赛制 | BO3／积分赛，单局结束保留总比分，整场结束再显示总冠军 | `MatchManager`、`GameSession`、`EndScreen`；需区分单局结果与整场结果 | 中 |
| 6 | 手柄与改键 | 玩家可以独立选择设备和修改按键，缓解三人共用键盘的空间与按键冲突 | `PlayerBase.ReadInput()` 是输入边界，现有 Input System 包可用；设备分配和持久化需要完整实现 | 中至高 |

优先级依据与当前玩法的契合度及已有代码复用程度，不是工期承诺。地图入口、规则设置、设备配置等涉及 UI 或交互结构的变化，实施前另行明确具体范围。

## 建议的首个扩展版本

先做 **机关地图内容包**：保持当前空场，另加一张中央障碍图和一张移动挡板图，先不叠加新道具与复杂敌人。重点验证障碍物如何改变路线、出界机会及合作生存空间。

下一步再加入 **一种有明显前摇的冲撞 AI**，让合作模式的变化来自敌人行为，而不只是数量和属性上升。若更重视聚会对战，则第二步改选多局赛制。

旧扩展方案中“多局赛制与正计时冲突”不是技术限制：单局计时与整场比分可以并存，应按想要的对局节奏决定。以上候选均未在本轮修改游戏实现。
