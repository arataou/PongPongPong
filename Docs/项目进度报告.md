## 摘要

本项目是一款基于 Unity 引擎开发的 2D 本地双人物理推挤对战游戏，玩家通过操控小球互相挤撞，将对手完全推出场地边界即获胜。游戏在传统 PvP 玩法上引入了**动态状态轮换机制**与**AI 干扰系统**两层动态变量，使每一局对战都呈现独特的战术路径与节奏。

截至本报告日期，**核心玩法逻辑（gameplay layer）已全部实现并完成自测**，包含 12 个 C# 脚本、共计 598 行代码、31 个 Inspector 可调参数，配套设计与调试文档 6 份。当前进入 UI 资源拼装阶段。

## 一、游戏玩法介绍

### 1.1 核心玩法

**两个小球，一个开放场地，把对手推下场即胜。** —— 这是表层规则。

但在这层简单规则之上，本项目设计了两套相互交织的**动态变量**：

1. **状态轮换机制**：每隔数秒，两位玩家各自随机获得一种状态（加速 / 变大 / 变小），属性发生显著变化，原有的战术平衡被打破。
2. **AI 干扰系统**：开局 60 秒后，红色 AI 球从场地边缘随机生成，主动追击距离最近的玩家。此后每 10 秒生成一只，永不停止。

两层机制共同构成游戏的**核心张力**：玩家既要应对随机切换带来的属性优劣势，又要在越来越拥挤的场地中躲避 AI 球的撞击，同时寻找机会推飞对手。

### 1.2 操作方式

| 角色 | 控制 |
|---|---|
| **P1（蓝球）** | `W` `A` `S` `D` |
| **P2（黄球）** | `↑` `↓` `←` `→` |

| 系统按键 | 功能 |
|---|---|
| `Esc` | 暂停 / 继续（弹出菜单，冻结时间） |
| `R` | 游戏结束后重开本局 |

### 1.3 状态系统

球体共有 **4 种状态**（`BallState` 枚举），每种状态通过对基础属性应用倍率实现，所有倍率均在 Inspector 中可配置：

| 状态 | 速度倍率 | 体积倍率 | 质量倍率 | 战术定位 |
|---|---|---|---|---|
| **Normal** | ×1.0 | ×1.0 | ×1.0 | 基准态 |
| **Fast**   | ×2.0 | ×1.0 | ×1.0 | 主动出击，绕后偷袭 |
| **Big**    | ×1.0 | ×1.6 | ×2.56（=1.6²） | 站桩防守，撞飞对手 |
| **Small**  | ×1.0 | ×0.6 | ×0.36（=0.6²） | 灵活闪躲，易被推飞 |

**设计亮点**：质量倍率按面积关系（缩放²）设计，使物理碰撞自然符合直觉。状态切换通过 `transform.localScale` 修改，**视觉与碰撞体同步**，无需单独维护碰撞器配置。

### 1.4 AI 系统

| 属性 | 说明 |
|---|---|
| **行为** | 每帧朝当前最近玩家直线追击（基于 `sqrMagnitude` 性能优化） |
| **属性** | 固定标准属性，**不受状态轮换影响**（设计上的减法，保证 AI 行为可预测） |
| **质量** | 远大于玩家基础质量，撞击对玩家形成显著推力 |
| **生成** | 从场地四边随机一点生成，朝场内移动 |
| **节奏** | 首只延迟 60 秒，之后每 10 秒一只，永不停歇且不补充（死亡后不重生） |

### 1.5 胜负判定

| 情况 | 结果 |
|---|---|
| 一方先被推出边界 → 另一方剩余 | **该玩家胜** |
| 双方相继出界（被 AI 同时挤死等） | **平局**，AI 不计入胜方 |

判定采用**事件驱动**：玩家球 `OnDestroy` 时触发 `MatchManager.CheckEnd()`，避免每帧扫描造成的性能浪费。结算时通过 `Time.timeScale = 0` 冻结全场，并触发 `OnMatchEnded` 事件供 UI 层订阅。

## 二、技术架构

### 2.1 代码组织

所有玩法脚本位于 `Assets/LogicScripts/`，按职责分为四层：

```
┌─────────────────────────────────────────────────────┐
│  UI 层（脚本就绪，等待资源拼装）                       │
│   HudController · PauseMenu · EndScreen              │
├─────────────────────────────────────────────────────┤
│  系统层（单例 + 事件）                                │
│   MatchManager · StateRouletteController · AISpawner │
├─────────────────────────────────────────────────────┤
│  角色层（抽象基类 + 多态）                            │
│   PlayerBase (abstract)                              │
│    ├─ PlayerController  (P1, WASD)                   │
│    └─ Player2Controller (P2, 方向键)                 │
│   AIController                                       │
├─────────────────────────────────────────────────────┤
│  场地与边界                                           │
│   ArenaBounds · BoundsKiller                         │
└─────────────────────────────────────────────────────┘
```

### 2.2 设计模式应用

| 模式 | 应用位置 | 解决的问题 |
|---|---|---|
| **抽象基类 + 多态** | `PlayerBase` → `PlayerController` / `Player2Controller` | 复用物理移动、状态机、生命周期注册等共性逻辑，只让子类实现输入读取 |
| **单例模式** | `MatchManager` / `StateRouletteController` / `AISpawner` / `ArenaBounds` | 系统级管理者全局唯一，避免重复实例 |
| **事件驱动** | `MatchManager.OnMatchEnded` Action | UI 层订阅而不轮询，胜负判定与展示解耦 |
| **注册-注销机制** | `MatchManager.RegisterPlayer/UnregisterPlayer` | 玩家生命周期与胜负检测自动同步，新增玩家无需改判定逻辑 |
| **组件化复用** | `BoundsKiller` 同时挂在玩家与 AI 球上 | 出界销毁逻辑一处编写、双处复用 |
| **Inspector 可配置化** | 31 个 `[SerializeField]` 字段 + `[Header]` 分组 | 把所有数值与策划/测试解耦，无需改代码即可调参 |

### 2.3 物理与碰撞设计要点

- **基于半径的精确出界判定**：`BoundsKiller` 使用 `CircleCollider2D.radius * lossyScale` 计算实际半径，使变大/变小状态下的出界判定符合视觉。
- **速度逼近而非直接设置**：`Rigidbody2D.linearVelocity = MoveTowards(...)` 实现加速度感，操作有重量、有惯性，避免"瞬移式"移动的廉价感。
- **质量与面积的物理一致性**：状态质量倍率 = 缩放倍率²，符合二维面积关系。

## 六、技术亮点小结

1. **代码与配置解耦**：所有数值参数均通过 `[SerializeField]` 暴露到 Inspector，非开发角色可独立完成调参。
2. **事件驱动而非轮询**：胜负判定通过 `OnDestroy` 触发，UI 通过订阅 `OnMatchEnded` 响应，无每帧扫描开销。
3. **抽象基类提取共性**：玩家逻辑通过 `PlayerBase` 抽象类提取，输入差异通过 `ReadInput()` 多态实现，新增玩家（如手柄玩家）只需继承基类。
4. **物理一致性**：状态质量倍率 = 缩放倍率²，符合二维物理直觉，碰撞表现自然。
5. **边界感知组件化**：`BoundsKiller` 独立组件可挂载到任意 `CircleCollider2D` 对象，玩家与 AI 复用同一套出界逻辑。
6. **可重玩性设计**：R 键快速重开、Esc 暂停，配合 BO1 短局制使单局节奏紧凑（预期 2-4 分钟），易于反复体验。
7. **完整的文档分层**：6 份文档按受众分工，从设计意图到调参手册全覆盖，体现工程化协作思维。
